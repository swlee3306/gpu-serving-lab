# verify-harness 결과 (2026-11-04)

로컬 LLM이 "검증 보조"로 쓸 만한지 재는 평가. 대상: 설계안 §3 예제를 옮긴 toy 모듈(`src/ingest.py`), 실제 pytest 실행 결과로 만든 24개 케이스.
vLLM 0.32.0(digest 고정), 3개 모델, temperature 0(T1/T2, 2회 반복) / 0.7(T4, 3샘플).

## T1 빨간불 분류 (48 = 24케이스×2)
| 모델 | 정확도 | 틀린 케이스 |
|---|---|---|
| Qwen2.5-3B | 46% | 거의 전부 behavior_failure로 찍음 (weakened 0/12, ok 0/6) |
| Qwen3.5-4B | **92%** | B_subset_only, B_stale_evidence → `ok`로 오판 |
| Qwen3.5-9B AWQ | 88% | 위 둘 + C_expected_changed → behavior_failure |
- 반복 일관성 24/24 (temp 0). 규칙 기반 baseline 100%는 데이터를 본 뒤 만든 것이라 낙관적.
- **위험한 오답**: 4B/9B 모두 "일부만 실행됨 / 오래된 증거"를 `ok`로 통과시킴. 설계안이 가장 경계하는 "검증 불완전"이 정확히 새는 지점.

## T2 검증 보고서 JSON
- 스키마 통과 100% / 96% / 92%, 범주 일치 67% / 78% / 86%, 존재하지 않는 테스트 이름 인용 0건(전 모델).
- 스키마 실패: 4B 2건(B_collection_error), 9B 4건(C_expected_changed, C_assertion_weakened).

## T4 테스트 제안 (변이 8개 중 적용 가능 6개를 죽인 수)
| 모델 | 유효 테스트 비율 | 샘플별 kill | 합집합 | 비고 |
|---|---|---|---|---|
| Qwen2.5-3B | 40% | 1/2/1 | 2 | 참조 구현에서 실패하는 테스트 18개(오경보) |
| Qwen3.5-4B | 27% | 5/0/0 | 5 | malformed 22개 |
| Qwen3.5-9B AWQ | 63% | 6/6/1 | 6 | 2샘플은 6/6 전부 |
- 무작위 시나리오 baseline: 평균 4.4/6. 9B가 잘 될 때만 이를 넘고, 샘플 편차가 큼.
- 수정 이력: 첫 실행은 `extract_json`이 배열 응답을 첫 객체로 잘라 T4가 전부 미파싱이었음 → 먼저 나오는 괄호 우선으로 고치고 저장된 원문을 `harness/rescore.py`로 재채점(모델 재실행 없음).

## 결론(추론 포함)
- 보조 분류기: Qwen3.5-4B/9B는 가능, Qwen2.5-3B는 불가.
- 단, LLM 판정은 게이트가 될 수 없음: 증거 범위/신선도 같은 메타 검증은 규칙으로 먼저 잡고, LLM은 설명·초안용.
- T4는 9B만 의미 있고 안정성이 낮음 → 변이 검사로 걸러 쓰는 "제안 생성기"로만.

## 한계
합성 24케이스, 모듈 1개, baseline이 사후 제작, T4 표본 3개, 모델당 1회 실행. 모델 간 작은 차이(88% vs 92%)는 유의하다고 못 함(케이스 단위로는 한 건 차이).

## 추가: 구독 모델(Claude / Codex) 비교 (2026-11-04)
같은 24케이스·같은 프롬프트. CLI(`claude -p --model sonnet`, `codex exec` 기본 모델)를 빈 임시 디렉터리에서 도구 없이 호출. **CLI는 온도를 지정할 수 없어 기본값**, T1/T2는 **1회**(로컬은 2회), T4는 3샘플.

| 모델 | T1 | T2 스키마 | T2 범주 | T4 유효 | T4 kill(샘플별) | 소요 |
|---|---|---|---|---|---|---|
| Qwen2.5-3B | 22/48 | 48/48 | 32/48 | 12/30 | 1,2,1 | 120s |
| Qwen3.5-4B | 44/48 | 46/48 | 36/48 | 8/30 | 5,0,0 | 176s |
| Qwen3.5-9B AWQ | 42/48 | 44/48 | 38/48 | 19/30 | 6,6,1 | 132s |
| Claude (sonnet) | **24/24** | 24/24 | 24/24 | 30/30 | 6,6,6 | 120s(병렬 4) |
| Codex (기본) | **24/24** | 24/24 | 24/24 | 30/30 | 6,6,6 | 223s(병렬 4) |

- 구독 모델은 B_subset_only / B_stale_evidence도 정확히 `verification_incomplete`로 분류. 로컬 4B/9B의 약점이 여기서 갈림.
- T4: 매 샘플 10개 테스트가 전부 유효하고 적용 가능 변이 6개를 모두 죽임(로컬 최고 9B는 6/6/1).
- 채점기 수정 2건: (1) 환각 검사 정규식이 한글 조사까지 `\w`로 붙여 오탐 → ASCII로 제한 후 재채점(로컬 결과 변화 없음), (2) counts가 정답 없는 케이스(타임아웃 등)는 집계에서 제외. 남은 1건(`test_ingest_v2`)은 누락된 파일 이름을 언급한 것으로 보이며 실제 환각 여부는 미확인.
- 한계: 이 toy에서는 두 모델이 천장(만점)이라 둘의 우열은 못 가름. 온도·반복 조건이 로컬과 달라 엄밀한 동일 조건 비교가 아님. 구독 모델은 비용/쿼터를 쓰고 코드가 외부로 나감.

## 추가: Mac mini(M4, 32GB 통합 메모리) 단독 실행 (2026-11-04)
`mlx-lm 0.32.2` 서버(전용 venv `~/lab/mlx`) + MLX 4bit 모델, 같은 24케이스·같은 프롬프트·temp 0 / 2회. 소요시간은 첫 요청의 모델 다운로드가 섞여 있어 **호출 중앙값**으로 비교한다. 양자화 방식이 GPU(AWQ/BF16 계열)와 달라 동일 가중치 비교는 아님.

| 실행 | T1 | T2 스키마 / 범주 | T4 유효·kill(샘플별) | T1 중앙값 | T4 중앙값 |
|---|---|---|---|---|---|
| GPU 4070Ti S · Qwen3.5-4B | 44/48 | 46/48 / 36 | 8·5, 0·0, 0·0 | 0.71s | 12s |
| Mac · Qwen3.5-4B 4bit | 42/48 | 48/48 / 40 | 미파싱, 9·5, 6·5 | 1.74s | 49s |
| GPU · Qwen3.5-9B AWQ | 42/48 | 44/48 / 38 | 10·6, 8·6, 1·1 | 0.54s | 9s |
| Mac · Qwen3.5-9B 4bit | 42/48 | 48/48 / 44 | 1·1, 9·6, 7·5 | 2.85s | 49s |
| **Mac · Qwen3.5-35B-A3B 4bit** | 44/48 | 48/48 / 44 | 10·6, 9·6, 10·6 | 1.55s | 20s |

- 속도: 같은 급(4B/9B)에서 Mac은 GPU보다 호출당 2.5~5배 느림(순차 호출 기준). 서버 상주 메모리는 4B 약 3GB, 9B 약 5.5GB, 35B-A3B 약 11~13GB(RSS).
- 품질: 4B/9B는 GPU와 거의 같음(B_stale_evidence·B_subset_only를 `ok`로 놓치는 약점 동일). 35B-A3B는 T4가 6/6/6으로 안정적이고 T2 범주 정확도도 가장 높지만 위 두 케이스는 여전히 놓침.
- 35B-A3B(MoE, 활성 3B)는 16GB VRAM GPU에는 들어가지 않지만 Mac에서는 9B보다 빠르게 돈다. Mac의 강점은 속도가 아니라 큰 모델을 올릴 수 있는 용량.
- 한계: 모델당 1회 실행, Mac mini는 다른 상시 서비스와 동시 운영 중이었고(부하 약 2.9), 동시 요청 처리량은 측정하지 않음. Mac 4B의 T4 한 샘플은 JSON 미파싱(원인 미조사).

## 추가: 전력 측정 (2026-11-04)
동일 부하(평가 49호출: T1·T2 24케이스×1 + T4 1샘플), 9B 4bit급. 측정 대상이 다름에 주의: Mac은 `powermetrics` 패키지 전력(CPU+GPU+ANE, DRAM·SSD·전원 손실 제외), GPU는 `nvidia-smi` **보드 전력만**(PC 본체 CPU/RAM/PSU 제외). 벽 전력계 측정은 아님.

| 실행 | 소요 | 평균 전력 | 에너지 |
|---|---|---|---|
| Mac mini M4 · 순차 1요청 | 368s | 13.7W (최대 24W) | 1.39Wh |
| GPU · 순차 1요청 | 61s | 216W | 3.66Wh |
| GPU · 8요청 동시 | 17s | 214W | 1.01Wh |
| 대기(모델 적재, 요청 없음) | - | Mac 패키지 0.2W / GPU 보드 44W(모델 없으면 약 17W) | - |

- 순차 처리 기준 Mac이 GPU보다 에너지를 약 2.6배 덜 씀. 동시 처리하면 GPU가 Mac보다 약 1.4배 덜 씀(처리량이 전력 증가보다 훨씬 큼).
- 상시 가동 비용은 부하 시 전력보다 대기 전력이 좌우. 위 표는 본체 전력이 빠져 GPU 쪽이 과소평가.
- 한계: 1회 측정, 요금 단가·벽 전력은 미측정(추정), 두 장비 양자화가 다름.
