## 2. 읽은 것
1. **`nvidia-smi` GPU 사용률은 용량 지표가 못 된다.** 6개 설정 모두 평균 100%(7B AWQ만 99.3%)로 구분이 안 된다. 이 값은 "측정 구간 중 커널이 하나라도 돌고 있던 시간의 비율"이라, 3B가 여유 있는 4건/초에서도 100%로 찍힌다. 연산 강도에 따라 달라진 것은 **전력**이다(3B 206W → 7B 244~249W → Qwen3.5-9B 238W). 용량 판단에는 **KV 사용률, 대기열, TTFT**가 필요하다 → Step 2 대시보드의 핵심이 된다.
2. **대기 VRAM은 모델 크기와 거의 무관하게 크다(11.9~13.6 GiB).** vLLM은 모델이 작아도 `util × 총 메모리`(약 13.2 GiB) 근처를 미리 잡는다. 다만 설정마다 예산을 전부 쓰지는 않는다(11,940~13,614 MiB, 원인은 확인하지 못함). 부하를 걸어도 VRAM 증가는 약 0.2~0.4 GiB뿐이다(이미 예약돼 있어서).
3. **같은 4건/초 부하에서 모델별 압박이 완전히 다르다.** 최대 KV 사용률: 3B 3.2% → 7B 약 11% → Qwen3.5-4B 50% → Qwen3.5-9B 77%. Qwen3.5는 가중치(8.4~8.6 GiB)가 커서 KV/상태 예산이 2.4 GiB뿐이라, 4건/초에서 이미 절반 이상을 쓴다. 도착률이 더 올라가면 **연산보다 KV/상태 자리가 먼저 한계**가 될 가능성이 크다(이번에 4건/초 이상은 재지 않았다).
4. 같은 부하에서 7B는 3B보다 TTFT p95가 약 2.7배(308 → 831ms), 1인 속도는 65 → 51 tok/s. 전력은 약 40W 더 쓴다.
5. 4건/초 TTFT p95는 3B fp16 308ms, 3B fp8 279ms로 SLO(300ms) 경계다. 이전 측정(A 313ms, B 279ms)과 비슷해 이 값은 재현된다.

## 3. max-model-len 실험
KV 메모리(GiB)와 대기 VRAM은 `max-model-len`을 바꿔도 **그대로**였다(Qwen2.5-7B GPTQ KV 6.16 GiB·대기 VRAM 약 12,756 MiB, Qwen3.5-4B KV 2.47 GiB·대기 VRAM 12,124 MiB; 7B 32768만 12,774 MiB). 바뀐 것은 로그의 KV "칸 수"와 "최대 동시성"이다.

| 모델 | max-model-len | KV 총칸 | 로그의 최대 동시성(= 총칸 ÷ max-model-len) |
|---|---|---|---|
| Qwen2.5-7B GPTQ (밀집) | 4,096 | 115,296 | 28.15× |
| | 8,192 | 115,296 | 14.07× |
| | 32,768 | 115,296 | 3.52× |
| Qwen3.5-4B (하이브리드) | 4,096 | 44,763 | 10.93× |
| | 8,192 | 56,971 | 6.95× |
| | 16,384 | 65,967 | 4.03× |
| | 32,768 | 72,659 | 2.22× |
| | 65,536 | 76,542 | 1.17× |

- **밀집 모델(Qwen2.5)**: KV 총칸이 `max-model-len`과 무관하게 고정이다. 로그의 "최대 동시성"은 "그 길이의 요청이 동시에 몇 개 들어가나"라는 **최악의 경우 값**일 뿐, 실제로는 짧은 요청이 훨씬 많이 들어간다. `max-model-len`은 메모리를 바꾸는 값이 아니라 **한 요청이 쓸 수 있는 최대 길이 상한**이다.
- **하이브리드(Qwen3.5-4B)**: 같은 메모리인데 `max-model-len`을 키울수록 보고되는 KV 총칸이 늘었다(44,763 → 76,542). 원인은 확인하지 못했다(상태 블록과 어텐션 블록의 할당 방식이 길이에 따라 달라지는 것으로 추정, 미검증).
- **65,536까지 16GB에서 시작은 된다**(Qwen3.5-4B 최대 동시성 1.17×: 6만 토큰짜리 요청 한 개 수준). 긴 컨텍스트를 쓰려면 동시 사용자 수와 맞바꿔야 한다.
- 실무 규칙: `max-model-len`은 **실제로 필요한 가장 긴 요청 길이**로 둔다. 필요 이상으로 키워도 메모리는 늘지 않지만, 긴 요청 하나가 KV를 많이 차지해 다른 요청이 대기할 수 있다. 줄이면 긴 요청이 거절된다.

## 5. 아직 모르는 것 / 한계
- GPU 사용률 100%를 포화 지표로 쓰면 안 된다는 해석은 값이 모든 설정에서 같았다는 관찰에 근거한다. DCGM의 다른 지표(SM active 등)는 이번에 보지 않았다.
- 설정마다 대기 VRAM이 예산(13.2 GiB)보다 낮은 이유, 하이브리드 모델의 KV 총칸이 `max-model-len`에 따라 달라지는 이유는 확인하지 못했다.
- 부하는 4건/초 한 점이다. 더 높은 도착률에서 Qwen3.5의 KV/상태 한계는 측정하지 않았다.
- 표본 30~34개(1초 간격)라 전력·온도의 순간값 분포는 정밀하지 않다.
